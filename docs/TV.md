# TV Contracts

Current behavior; the original wish plan is historical. Shared storage and cloud rules: [DATA-CONTRACTS.md](DATA-CONTRACTS.md).

## Data and ratings

- `workspace.tvShows`: local IDs plus optional unique TMDB TV IDs; minimal tombstones for deletion. Duplicate provider identities are rejected. Backups/recovery/sync include nested seasons/episodes; disjoint shows merge, differing copies require an explicit choice.
- My Status: Watching, Airing · Caught Up, Caught Up, Want to Watch, Completed, Stopped (dropdown and ascending status-sort order). Independent of conservatively mapped provider activity (Active/Ended/Canceled/Upcoming/Unknown). Conflicting metadata is Unknown; never infer completion or cancellation.
- Airing · Caught Up is an explicit personal choice for following the current season as episodes arrive; it distinguishes weekly viewing from the existing Caught Up choice between seasons. It is never inferred from provider activity or dates. Like Caught Up, it displays/sorts/filters as Watching when saved aired episodes are unwatched, returning to Airing · Caught Up when progress catches up. Advance/catch-up preserves the saved weekly choice. Refresh, imports, backups and sync preserve it; legacy statuses keep their existing meaning.
- Latest watched episode has separate numeric Season and Episode inputs in the editor (whole numbers 1–100000, both supplied or both blank), or choose Watched through here beside a regular episode. It still saves to the existing `lastWatched` text field as `S2 E4`; legacy markers remain readable without requiring users to type prefixes. Opening/saving an unrecognized legacy marker without editing the numeric fields preserves it. This marker takes precedence over episode ratings, can move backward, and does not change ratings/notes. When blank, the highest regular, non-orphaned watched/rated (>1) episode provides progress. Legacy free text stays readable; unrecognized markers require correction before release tracking works.
- New episodes sums the unwatched remainder of each regular season after the marker. Loaded seasons count dated, non-orphaned episodes aired by today in the device's local calendar. If an earlier season is incomplete but a later season has released episodes, use that earlier season's provider episode total minus watched progress; explicit future dates prevent this estimate. The current release season counts only known aired episodes. This avoids showing only the latest season's count when older details have not yet been downloaded. Future episodes, specials and empty seasons are excluded; undated episodes are counted only through that historical season-total fallback. The Progress column displays the watched episode, a green catalog checkmark when caught up, or a red `-X` count (the tooltip identifies incomplete details as a lower bound). Both buttons stay enabled even with no watched progress. `>` starts at S1 E1 when no progress is available, otherwise advances to the next saved episode (including future episodes) or increments the episode number when details are absent. Known season boundaries move to the next season. `>|` marks the latest known release watched; if release details are unknown it asks for a refresh without inventing an episode. Both preserve ratings/notes, save immediately, and reject an open editor or changed record. Reaching the latest release changes Watching/Want to Watch to Caught Up, preserving Completed/Stopped. A saved Caught Up status displays, sorts, searches and filters as Watching while that count is positive, returning to Caught Up as progress advances. Other personal statuses remain unchanged. The automatic Watching display is derived, not a saved status rewrite or streaming-availability guarantee. Unknown or incomplete episode details do not establish that a show is caught up.
- Personal show, season and episode ratings display exactly one decimal place in tables, dropdown labels and editor controls (4.0, 4.5); stored numeric values and integer wishlist priorities are unchanged. Progress check/behind indicators align right immediately before the advance buttons. Show scores: nullable half-points 0–5. Season scores: nullable integers 1–10. Episode scores: nullable half-points 1–10. Labels live in `core/tv.js`; zero is a real show score, blank means unrated.
- Want to Watch uses nullable integer priority 1–5 (1 highest) in the # column and editor. Other statuses show the personal rating. Priority and rating are independent, retained through status changes, metadata refresh, imports, backups and sync. # sorting uses the displayed value, with non-wishlist rows before wishlist rows and blanks last within each group.
- Episode score >1 sets watched; 1 means Did not Finish and clears watched; clearing a score retains watched. Show score stays manual. Separate season/episode averages include DNF, exclude blanks and season 0. The editor also labels an aggregate including specials.
- Episode/season notes and `seasonRanking` are plain text, capped at 20,000 characters each. Escape in UI, preserve in refresh/backup/sync. Legacy `mode` and watched flags remain readable. Episode air dates appear beside progress controls.
- Limits: 2,000 shows; 500 seasons/show; 5,000 episodes/season; 30,000 loaded episodes/show; TV/full imports ≤5 MiB. Render episodes in pages of 50.

## Views and widths

- Linked shows have a row refresh button and a right-aligned TMDB link in the Show column. The link and row refresh use the supplied circular SVGs in the shared catalog; episode advance/catch-up use the supplied filled-square SVGs. Accessible labels/tooltips remain on all controls. The link uses the validated numeric TV ID, opens a separate tab with `noopener noreferrer`, and does not open the editor. Row refresh saves recovery, refreshes only that show and its tracked seasons, rejects open/concurrently changed copies, and commits before reporting success. It shares Stop/single-flight behavior with Refresh Show Data; unlinked shows omit both controls.
- TV view tabs, search, status filter, actions, dismissible status and list filter disclosure share a sticky control area below the measured app header. Narrow layouts up to 1350px keep controls on one line; secondary actions open in More and filters open in bounded popovers to retain content space. List rows scroll within the remaining viewport with sticky table headers; the same control area stays visible over the Pivots view. Status text has a leading close button; dismissal clears only that message and retains Stop during an active refresh. Later progress/completion messages can appear again.
- TV List has a Filters disclosure. TV Pivots has Type/Genres/Networks cards independent of list filters. Count each show once per group; average only rated shows, including zero. Adjusted scores use rated count and the movie formula (baseline 3, weight 5).
- Non-score list sorts break ties by descending personal rating, or ascending wishlist priority, blanks last, then title. Status sorting uses the viewing order above, reversible on a second click. Resizing changes only the selected column and table width; every column to its right shifts without changing width.
- TV preferences are device-local. Pivot widths persist per card/column; searches/minimums/sorts are session-local. Episode widths are shared across seasons: Notes initially fills available space; the first resize persists all three widths (Episode, # and Notes). Later resizes change only the selected width, retaining neighboring widths and allowing horizontal scrolling.
- The list orders Status, S, E, Last Air, Latest, Progress. Status is provider activity; My Status remains personal. Latest shows the highest aired regular episode in saved details. Seasons reporting zero episodes are ignored, including unloaded placeholders with no air date or an old air date; they cannot hide a known latest episode or block catch-up. A dash remains when no released episode is known or a later nonempty season still needs details. Both episode columns sort by numeric season/episode and retain device-local widths/sorts. Show has a measured minimum that includes the entire title plus its controls, including when a saved/manual width is narrower. Progress automatically fits its marker, indicator and buttons, overriding old fixed widths and omitting its resize handle. Both recalculate for text-size and viewport changes. S/E default to measured content widths (old 65px defaults shrink); their custom widths remain adjustable.
- The desktop editor uses 90% of viewport width/height; phone editors fill the dynamic viewport. Show details start collapsed in either view. Fully rated saved episodes with known counts covered open compactly with seasons expanded. Notes grow to fit text; names/scores center vertically. View changes preserve drafts.

## TMDB and imports

Explicit show/season refresh only; no polling. Preserve personal data and downloaded episodes. Match stable provider IDs before numbers; retain missing provider entries as orphaned for review, including their ratings in averages. Batch refresh commits recovery to IndexedDB (with localStorage fallback), rejects intervening edits while preparing it, processes all linked shows regardless of list filters, skips edited/changed shows, and saves each completed show atomically before counting success. Failed writes keep that show’s prior live/stored data and earlier completed shows. Draft saves reject concurrent changes. Show deletion uses IndexedDB recovery with the existing localStorage fallback, then atomically persists a minimal tombstone. It rejects library/draft changes while recovery is pending and keeps the editor/show intact if recovery or the write fails. The active library is never removed to make deletion fit. Do not store raw provider payloads or credentials.

Show refresh (including the row refresh, Check for new episodes and Refresh All) also downloads seasons at/after known progress, excluding empty seasons and seasons with future start dates. Shows without usable progress download all nonempty, non-future regular seasons so the behind count covers the whole series. Linking a TMDB show does the same. A failed/aborted season request or changed season identity discards that show's entire pending refresh; batch retains previously saved shows. The editor rejects refresh results when its draft changes in flight. Save Show keeps refreshed details offline. Without a refresh, release highlights use only saved episode details, evaluated when TV renders. All progress data uses existing backup/sync fields; no schema change is required.

TV → Import Shows accepts `{format: "top-shelf-tv-import", version: 1, shows: [...]}`. Rows require title, nullable half-point show rating and valid personal status; optional fields include priority (1–5), notes, TMDB ID, nested seasons/episodes and source seriesStatus Active/Unknown. Preview validates the whole result and allows row selection. Apply rejects stale previews and rolls back failed persistence.

Existing title matches can gain a missing TMDB ID. Detailed imports fill missing seasons/episodes and blank ratings/notes; never replace populated personal values. Match episode IDs/titles before numbers and reject conflicting numbered titles. Skip repeated unchanged details, duplicate identities and prior import tombstones. Since this is additive, it does not create a full-library recovery copy. Source Active uses `providerStatus: "Imported: Active"` until provider refresh. Personal files stay in ignored `import-preparation/`, not runtime assets.

## One-time data behavior

- Dexter/The Wire seed supplied season rankings only when `seasonRanking` is absent; explicitly empty remains empty.
- Sherlock seeds 13 supplied episode scores into missing values once. `sherlockRatingsAdded` protects later edits/clears; season 0 holds The Abominable Bride. Season averages are calculated, not personal season scores.
- The September 29 TV-note reset is independent of September 28: startup recovery first, local completion marker before replacement, TV show notes only. New notes, recovery restores and later imports are not cleared again. Failed persistence keeps the library and removes the marker for retry. Keep this marker stable unless another reset is explicitly requested.

Local schema 9 and cloud v8/schema 12 introduced TV priority and half-point show scores. Current cloud v9/schema 13 adds formatted Overall Notes; cloud v1–v8 remain readable. Update all app copies before syncing; older clients reject the new envelope.
